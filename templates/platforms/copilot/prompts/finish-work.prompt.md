# 收尾工作

收尾当前会话：归档当前任务（以及用户想顺手清理的其他已完成但未归档的任务），并记录会话日志。代码提交不在这里做——提交发生在工作流阶段 3.4，在调用本提示词之前。

**时机**：阶段 3.4（提交改动）之后——此时工作树已经干净。

---

## 步骤 1：调查当前状态

```bash
sunshine task context --mode record
```

这会打印：

- **我的进行中任务**——看看除了当前任务之外，是否还有实际已完成（代码已合并、验收标准已满足）应该在本轮归档的任务。
- **Git 状态**——快速看一下哪些文件是脏的。
- **最近提交**——步骤 4 的 `--commit` 需要用到它们的哈希。

如果 `--mode record` 发现其他与当前会话无关的已完成任务，向用户一次性确认：“这 N 个任务看起来已经做完了——本轮顺便一起归档吗？[y/N]”。默认是否；当前任务无论如何都在步骤 3 归档。

## 步骤 2：合理性检查——给脏路径分类

运行：

```bash
git status --porcelain
```

排除 `.sunshine/workspace/` 与 `.sunshine/tasks/` 下的路径——这些由 `sunshine task add-session` 与 `sunshine task archive` 的自动提交管理，在本提示词自己的工作过程中出现脏状态是正常的。

对剩下的每条脏路径，判断它属于**当前任务**还是**其他并行工作**（例如另一个终端窗口在编辑同一仓库）。判断方法：

- 当前任务的 `prd.md` / `implement.jsonl` / `check.jsonl` 里引用的路径 → 当前任务
- 代码区域与任务所述范围相符，或你记得本会话编辑过 → 当前任务
- 无关区域的路径，本会话完全没有印象动过 → 其他并行工作

然后按以下方式处理：

- **仍有路径看起来是当前任务的工作**——退出并提示：
  > “工作树里有本任务未提交的代码改动：`<列表>`。请先回到工作流阶段 3.4 提交它们，再运行 `/finish-work`。”

  不要在这里运行 `git commit`。不要提示用户提交。用户回到阶段 3.4，AI 在那里驱动批量提交。
- **其余路径看起来都无关**（其他并行窗口的工作）——提示一次然后继续步骤 3：
  > “提示：本任务范围之外的脏文件——留给另一个窗口处理：`<列表>`。”
- **确实拿不准**——问用户一次：“`<列表>` 是本任务我忘了提交的工作，还是另一个窗口的？（提交 / 忽略）”——然后按回答处理。

## 步骤 3：归档任务

```bash
sunshine task archive <task-name>
```

至少归档：当前任务（如果有）。再加上用户在步骤 1 确认的其他任务。每次归档都会由脚本自动提交产生一个 `chore(task): archive ...` 提交。

如果没有当前任务，用户也没有确认其他清理归档，跳过这一步。

## 步骤 4：记录会话日志

```bash
sunshine task add-session \
  --title "Session Title" \
  --commit "hash1,hash2" \
  --summary "Brief summary"
```

`--commit` 用阶段 3.4 产生的工作提交哈希（见步骤 1 的 `Recent commits` 列表，或用 `git log --oneline` 查看）。不要包含步骤 3 的归档提交哈希。这会产生一个 `chore: record journal` 提交。

最终 git log 顺序：`<3.4 的工作提交>` → `chore(task): archive ...`（一个或多个）→ `chore: record journal`。

## 与其他命令的关系

```
Development Flow (workflow.md Phase 3):
  3.2 调试复盘（按需）
  3.3 规范更新
  3.4 提交改动  -> AI 起草批量提交，用户确认
  3.5 收尾      -> /finish-work（本提示词：调查 + 归档 + 日志）
  （3.1 已并入 2.2 + 3.4——见 workflow.md “Phase 3: Finish”注释）

Debug Flow:
  遇到 bug -> 修复 -> /break-loop -> 知识沉淀
```

- `/finish-work`——调查 + 归档 + 记录会话（本提示词）
- `/break-loop`——调试后的深度分析

---

## 核心原则

> **收尾工作只是记账。** 代码在运行它之前已经提交了。如果工作树是脏的，本提示词拒绝继续。
