# 收尾工作

收尾当前会话：归档当前任务（以及用户想顺手清理的其他已完成但未归档的任务），并记录会话日志。这里不做代码提交——提交在工作流阶段 3.4 完成，在调用本命令之前。

## 步骤 1：查看当前状态

```bash
sunshine task context --mode record
```

输出包括：

- **我的进行中任务**——检查除当前任务外是否还有确实已完成（代码已合并、验收标准已满足）、本轮应归档的任务。
- **Git 状态**——快速看一下哪些文件是脏的。
- **最近提交**——步骤 4 的 `--commit` 需要用到它们的哈希。

如果 `--mode record` 发现其他与本会话无关的已完成任务，向用户一次性确认：“这 N 个任务看起来已完成——本轮一并归档吗？[y/N]”。默认为否；当前任务无论如何都在步骤 3 归档。

## 步骤 2：合理性检查——给脏路径分类

运行：

```bash
git status --porcelain
```

过滤掉 `.sunshine/workspace/` 与 `.sunshine/tasks/` 下的路径——它们由 `sunshine task add-session` 与 `sunshine task archive` 的自动提交管理，本 skill 自身的工作也会让它们变脏。

对其余每条脏路径，判断它属于**当前任务**还是**其他并行工作**（例如另一个终端窗口在编辑同一仓库）。判断依据：

- 当前任务的 `prd.md` / `implement.jsonl` / `check.jsonl` 中引用的路径 → 当前任务
- 与任务所述范围匹配的代码区域中的路径，或你记得本会话改过的路径 → 当前任务
- 无关区域中的路径，且本会话没有动过它们的印象 → 其他并行工作

然后分流：

- **仍有路径看起来是当前任务的工作**——直接退出并提示：
  > “工作区有本任务未提交的代码改动：`<list>`。请先回到工作流阶段 3.4 提交，再运行 `{{CMD_REF:finish-work}}`。”

  不要在这里运行 `git commit`，也不要提示用户提交。用户回到阶段 3.4，AI 在那里驱动批量提交。
- **其余路径看起来都无关**（其他窗口的工作）——提示一次后继续步骤 3：
  > “提示：任务范围外的脏文件留给另一个窗口处理：`<list>`。”
- **确实无法判断**——问用户一次：“`<list>` 是我忘记提交的本任务工作，还是另一个窗口的？（提交 / 忽略）”——然后按回答分流。

## 步骤 3：归档任务

```bash
sunshine task archive <task-name>
```

至少归档当前任务（如果有），再加上用户在步骤 1 确认的其他任务。每次归档都会通过脚本的自动提交产生一条 `chore(task): archive ...` 提交。

如果没有当前任务，且用户也没有确认需要清理归档的任务，跳过本步骤。

## 步骤 4：记录会话日志

```bash
sunshine task add-session \
  --title "Session Title" \
  --commit "hash1,hash2" \
  --summary "Brief summary"
```

`--commit` 使用阶段 3.4 产生的工作提交哈希（见步骤 1 的 `Recent commits` 列表，或用 `git log --oneline` 查看）。不要包含步骤 3 的归档提交哈希。本步产生一条 `chore: record journal` 提交。

最终 git log 顺序：`<3.4 的工作提交>` → `chore(task): archive ...`（一条或多条）→ `chore: record journal`。
