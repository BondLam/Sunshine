开始任务前，先阅读相关的开发指南。

按以下步骤执行：

1. **阅读当前任务产物**：
   - `prd.md`：需求与验收标准
   - `design.md`（如果有）：技术设计
   - `implement.md`（如果有）：执行顺序与验证计划

2. **发现包及其规范层**：
   ```bash
   sunshine task context --mode packages
   ```

3. **判断哪些规范适用**，依据：
   - 你要改的是哪个包（例如 `cli/`、`api/`）
   - 工作类型（后端、前端、单元测试、文档等）
   - 任务产物中引用的规范/调研路径

4. **阅读每个相关模块的规范索引**：
   ```bash
   cat .sunshine/spec/<package>/<layer>/index.md
   ```
   遵循索引中的**“开发前检查清单”**一节。

5. **阅读开发前检查清单中列出的、与任务相关的具体指南文件**。索引不是目标——它指向真正的指南文件（例如 `error-handling.md`、`conventions.md`、`mock-strategies.md`）。阅读这些文件，了解编码标准与模式。

6. **始终阅读共享指南**：
   ```bash
   cat .sunshine/spec/guides/index.md
   ```

7. **对于非平凡任务，写代码前先说明改动边界。** 非平凡指：涉及多个文件、跨层、改动公开接口，或修改不是你刚写的代码。写下：
   - 现在的行为与应有的行为之间最小的行为差距
   - 该行为实际所在的位置（而不是最容易拦截的位置）
   - 预计要改哪些文件，以及每个文件为什么必须改
   - 本任务明确不做什么
   - 如果需要局部重构，如何证明它没有改变行为

   小而范围明确的改动不需要这一步——直接做。

   如果实际范围明显比这更大，先说明情况与原因再继续。不要自行扩大改动范围。

8. 了解需要遵循的编码标准与模式，然后按开发计划继续。

这一步在写任何代码之前**必须**完成。
